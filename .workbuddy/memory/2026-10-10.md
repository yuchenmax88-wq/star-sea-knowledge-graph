## 第二轮：扩到 2200 节点 + three.js 三维化

用户要求「500mb 的知识库，多 agent，保证正确、连贯、有关联，加 three.js 增加互动性」。

**先给了 500MB 的硬限制**（写进最终回复）：V8 单字符串上限 5.37 亿字符 → 一个 500MB JSON 连
`JSON.parse` 都跑不了；GitHub 单文件 >100MB 直接拒收；Pages 站点 ≤1GB / 软带宽 100GB 月；
力导向画布上万节点就崩；2.5 亿字要保证正确不可能。结论：不做 500MB，做「能撑住的最大规模」，
并把架构做成可无限加料。

**规模**：20 个领域 × 110 = 2200 节点、3320 条领域内边、2437 条跨领域边、2200 条详解（每条 120~220 字）。

**做法**：20 个 agent 各写一个 `domains/<id>.js`（提示词里写死节点数、id 前缀、关系类型配比、禁止编造）；
9 个 agent 分头补 `edges/cross-*.js`；20 个 agent 写 `text/<id>.js`。
每个 agent 都必须自己跑 `tools/validate*.js` 通过 ALL OK 才算完成 —— 这一步是质量闸门。

**本轮修掉的问题**：
1. `KG.build()` 没给 link 建 `na/nb` 节点引用 → 渲染层全取不到坐标（渲染成空气）。
2. 跨领域弹簧把 20 个星座拽成一团 → 改成跨领域边完全不参与力布局，只画线。
3. 节点精灵半径是 `r*2*3.4`，每个节点变成 34px 大光球，把标签全盖住 → 降到 `r*2*2.2` 并削弱光晕。
4. 标签没描边，压在亮节点上读不清 → 加 `strokeText` 深色描边。
5. 取景用包围盒估算太保守（内容只占 23% 画面）→ 改成投影迭代量占比，并居中。
6. 每帧重解析 2200 次颜色字符串 + 无变化也重传顶点 → 颜色缓存 + 状态签名比对。
7. 2D 降级渲染器缺 `fit()`，报 `R.fit is not a function` → 补上，并加 `?r=2d` 强制切换。
8. 窄屏上 20 个领域名糊成一片 → 领域名与节点标签共用占位表做防重叠。

**新增**：three.js r128 本地内置（603KB，UMD 走 script 标签，无 CDN）；2D/3D 视图切换按钮；
`assets/data/text/` 懒加载分片（点到节点才注入 script，file:// 下也能用）。

最终自检：2200 节点 / 5757 关系 / 20 领域 / 0 孤立节点；搜索、详情分组、领域与关系类型过滤、
暂停、标签、自动旋转、2D 切换全部通过；三维与二维两条路径控制台均无报错。

## 第三轮：独立语义核查 + 修正

之前只做过结构校验（语法/悬空 id/孤立节点/字数），**没人查过内容对不对**。补了这一课。

**派了 5 个只读核查 agent**：电气类节点定义、信息类节点定义、跨领域关系、领域内关系、详解正文。
提示词里刻意写死「必须真懂再判、不确定标存疑、**允许报告"没发现实质错误"**」——不设指标，否则核查会变成走过场。

**核查结论**：节点定义抽查 1074 条，实质错误率 **0.4%**；详解 136 条全读 8 个文件，A 类 0 条 B 类 0 条；
关系类问题较多（跨领域 13~15% 存疑，方向/类型错误约 5%）。

**修掉的问题（按重要性）**：
1. **4 条实质知识错误**：`power-body-diode` 把体二极管安到 IGBT 头上（IGBT 没有固有体二极管）；
   `circuit-magnetic-material` 自相矛盾（前半句只描述铁磁质，后半句却把抗磁质也算进"磁性材料"）；
   `math-z-transform` 写成"积分变换"（Z 变换是幂级数，且同仓库 signal.js 写对了，自相矛盾）；
   `math-lagrange-interpolation` 说余项用"节点处导数"估计（那是埃尔米特插值，张冠李戴）。
2. **`part` 方向全量归一化（最大一块）**：20 个领域里 17 个写「整体→部件」、3 个（code/math/protect）
   写反了，power 还混着 5 条例外。**根因是我生成时给的示例"「变流器」由「开关器件」组成"没写明方向**。
   用脚本翻转 49 条，并把标签从「组成」改成**「包含」**（"电力系统 组成 配电"是病句，"包含"读得通）。
3. **27 条同名节点之间被标成前置/应用/包含** —— 同一概念不可能是它自己的前置。这是个**客观可验证**的缺陷，
   写脚本全量查出后统一改为 related。
4. 删除 3 条硬凑的跨领域边（如「图」↔「甘特图」，只是名字都带个"图"字）。
5. 修正 8 条方向反了/类型标错的边，6 处同名异概念重命名（短路电流→光伏短路电流、量化→模型量化等），
   `protect-mho-relay` 这个错 id 改名（mho 指方向阻抗继电器，节点却是全阻抗继电器）。

**教训**：核查者也会出错 —— 跨领域核查报告里它把 part 的约定说拧了（自称"部件→整体"却把
"振荡闭锁→距离保护"判为反了，而振荡闭锁恰恰是距离保护装置的部件）。**报告只能当线索，每条都得自己复核**。

**流程教训**：写批量改文件的脚本时，正则替换里捕获组已经带了引号，我又加了一层引号，
产生 `""part""` 把 8 行写坏。**批量改写必须先预览、再校验语法**。
事后已修掉脚本本身（`edge-surgery.js`），并给它加了「写完立刻 `new Function` 语法自检，失败 exit 1」这道闸；
用 `md5sum 数据文件 | md5sum` 跑两遍比对指纹验证了幂等。
