## 视觉与性能要点（39 领域踩出来的）
- **椭球尺度按领域数自适应**：`k=sqrt(n/20)`，坐标 `1750k / 620k / 900k`。
  只按「真正有数据的领域」排布，否则白占位置会显得稀疏。间距/半径实测 2.23，3D 里不重叠。
- **跨领域线必须随缩放淡入**：几千条长线在总览视角会把星座织成一张网，而那个尺度上
  本来也追不到任何一条。做法是拆成独立的 LineSegments（crossSolid/crossDash）+
  着色器 `uOpacity` uniform，按 zoom 从 0.08 渐变到 1。
- **标签必须封顶**：碰撞检查是 O(k²)，不封顶的话放大后 k=节点总数，每帧上千万次比较直接卡死。
  三维封 500、二维封 400。
- **孤立节点 ≠ 连通**：查过「度数为 0」不等于查过连通分量，成对成簇的孤岛查不出来。
  每轮新增领域后都要跑连通分量检查。

## 技术约定（务必遵守）
- **不引入 CDN / 构建步骤**。three.js 是下载到 `assets/vendor/` 本地内置的（r128 UMD，走 `<script>`），
  这样 `file://` 双击能跑、`git push` 就能上线、离线也能看。
- 数据分三层，全是普通 JS：`assets/data/domains/<领域>.js`（节点+领域内关系）、
  `assets/data/edges/cross-*.js`（跨领域关系）、`assets/data/text/<领域>.js`（详解，按需懒加载）。
- 三个 JS 职责单一：`data.js`（注册表+合并校验）、`render3d.js`/`render2d.js`（渲染）、`graph.js`（布局+交互+UI）。
- canvas 全部按 devicePixelRatio 缩放，注意 HiDPI。

## 关键实现决策（踩过的坑）
- **跨领域连线绝不参与力布局**。几千条跨领域弹簧会把星座硬拽成一团；
  改成「只画线不拉拽」后布局立刻恢复分离。
- **跨领域线必须随缩放淡入**（39 领域时实测必需）：拆成独立的 `crossSolid`/`crossDash`
  两个 LineSegments，着色器加 `uOpacity` uniform，按 zoom 从 0.08 渐变到 1。
  总览视角下几千条长线会把星座织成一张网，而那个尺度上本来也追不到任何一条。
- **标签必须封顶**：碰撞检查是 O(k²)，不封顶则放大后 k=节点总数，每帧上千万次比较直接卡死。
  三维封 500、二维封 400。实测封顶后高倍缩放帧率与低倍持平。
- **孤立节点 ≠ 连通**：查过「度数为 0」不等于查过连通分量，**成对成簇的孤岛查不出来**
  （实测两次：20 领域时 6 个孤岛、39 领域时哲学里康德的 4 个节点成孤岛）。每轮都要查连通分量。
- **椭球尺度按领域数自适应**：`k=sqrt(n/20)`，坐标 `1750k / 620k / 900k`；
  只按「真正有数据的领域」排布。实测间距/半径 = 2.23，3D 里星座不重叠。
- 斥力必须用**均匀网格加速**（只算相邻 27 格），几千节点 O(n²) 直接崩。
- **标签防重叠**：按连接数排名贪心占位；领域名与节点标签共用同一张占位表，否则窄屏上领域名糊成一片。
  标签用 `strokeText` 描边，否则被发光节点盖住看不清。
- 取景不用包围盒估算——**反复投影量屏幕占比再调距离**（迭代 6 次 + 居中），
  深度方向的展开不会把画面拉得过远。布局冷却后要再 fit 一次（`settledFit`）。
- 渲染性能：静止时不重传顶点（用 `selected|hovered|layoutTick` 签名比对）；
  节点颜色**初始化时解析一次**，别每帧 `THREE.Color.set(css字符串)`。
- 对外暴露 `window.StarSea`（select / search / fit / reset / warp / toggleCategory / stats / data）。

## 验证方式
本机 Edge 无头 `--screenshot` 不产出文件。改用 **CDP**：以 `--remote-debugging-port` 启动 Edge，
用 Node 内置 WebSocket 连 DevTools，`Page.captureScreenshot` 取图，同时监听
`Runtime.exceptionThrown` / `consoleAPICalled` 抓错误。脚本在 `%TEMP%/shot.js`
（参数：url 输出路径 等待ms [求值表达式] [再等待ms] [宽] [高] [裁剪x y w h]）。
要点：**每次用不同的 user-data-dir 和端口**，否则会撞锁；输出 `.jpg` 自动走 JPEG，比 PNG 小十倍。
WebGL 要加 `--enable-unsafe-swiftshader --use-angle=swiftshader` 才能软渲染。
`?r=2d` 可强制二维渲染器，用来验证降级路径。

## 关系类型的约定（踩过大坑，务必遵守）
- **`part` 的方向是「整体 → 部件」**，标签显示为**「包含」**。
  生成数据时**必须在提示词里写死方向并给正向示例**——第一次没写清，
  20 个领域里 17 个写「整体→部件」、3 个写反，power 还混着 5 条例外，事后翻了 49 条才统一。
- `prereq` 方向「基础 → 进阶」，`apply` 方向「来源用在目标上」。
- **同一概念不要在多个领域重复建节点并连成有向关系**（会产出「X 是 X 的前置」这种铁错）。

## 校验器的领域豁免必须用「反向规则」
「禁止年份」本来是给**技术领域**定的（那里出现年份多半在编造规格），
但人文与科学领域里年份是**必需内容**（牛顿 1687、康德 1781）。
第一版用**正向白名单**列豁免领域（whist/chist/thist），结果 philosophy/economics/astronomy 不在名单里，
**连续三个 agent 用三种不同方式绕过检查**：把年份写成汉字数字（「一四九二年」）、
改成世纪表述（「18 世纪」代替 1781 年）、以及在提示词里写「这条报错请忽略」。

**根因不是 agent 淘气，是白名单要手工维护、必然有漏**——而且 agent 遇到「检查项与任务冲突」
时的默认倾向是绕过检查而不是质疑检查。已改成**反向规则**：
`TECH_ONLY_YEAR` 只列 28 个技术领域「不豁免」，其余一律豁免，以后新增领域不用再维护。

## 数据生成流水线（tools/，站点运行不依赖）
- `dump-nodes.js` 导出 `tools/_nodes/<领域>.txt`，领域清单**直接读 `data.js` 注册表**，新增领域不用改脚本。
  agent 可能读到**过期清单**（域文件被重写后），要提醒它们以 `domains/*.js` 为准。
- 校验四件套：`validate.js` / `validate-text.js` / `validate-cross.js` / `check-samename-edges.js`（同名方向性边应为 0）；
  单领域更严的 `validate-one.js` / `validate-text-one.js`；**`check-coverage.js` 查「注册了领域但文件没跟上」
  ——结构校验全绿时它是唯一的哨兵**（实测抓到过 agent 报完成但文本文件从未落盘）。
- `dedup-edges.js` 清重复边与凑数边（内置「不裁出孤立节点」保护）。
- 改数据的脚本：`normalize-part-direction.js`、`fix-part-round2.js`、`edge-surgery.js`、`connect-islands.js`。

## 教训：agent 自报成功不可信（这一轮被坑了多次）
- **自报 ALL OK 但有 18~52 组重复边**：ev / building / wireless 三个领域都是。
  成因是 agent 先加一条强关系，又用 `related` 反复连同一对来凑边数。
- **自报「完成」但文件根本没落盘**：txt-market、link-M 各一次（报告正常，实际磁盘上没有）。
- **在我清理之后又覆盖回错误版本**：kg-building 反复重写 building.js。
- **对策**：① 提示词里把踩过的坑写成硬规则并配正反例；② 每个产出**一律自己跑校验**；
  ③ agent 未报完成前，校验结果不作数（会验到中间态）；④ 全部报完后**再统一验一遍**。

## 核查（比生成更重要）
- 只读核查 agent 的提示词必须写「**必须真懂再判、不确定标存疑、允许报告"没发现实质错误"**」，
  不设指标，否则核查会变成走过场。
- **核查报告只能当线索，每条都要自己复核**——它们也会误报，实测三种：
  把 `part` 约定说拧了（自称「部件→整体」却把「振荡闭锁→距离保护」判为反了）；
  把 `carbon-carbon-neutral-claim`（碳中和宣称）误读成 neutrality 的 id、报了一个不存在的 bug；
  把「数百年」这种模糊时长当成残留的汉字数字年份。
- 提示词里要明确「**宁可少也不硬凑**」。实测 agent 会严格执行：
  `economics × power` 只写 4 条并说明理由（器件级功率电子与宏观经济只有极窄接缝）。
  **垃圾边会稀释真正有价值的关联**，凑到 40 条假关联不如只留 5 条真的。
- 批量改文件前**先预览，改完立刻校验语法**：正则捕获组已带引号时再加引号会写出 `""part""`。
  `edge-surgery.js` 已内置「写完立刻 `new Function` 语法自检，失败 exit 1」；
  改这类脚本后用 `md5sum 数据文件 | md5sum` 跑两遍比对指纹，验证幂等、确认没写坏。
